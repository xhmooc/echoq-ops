## 6. 正确性与并发

- **发布幂等**：`jobs` 唯一约束为 `(draft_id, IFNULL(account_id,-1))`，领取使用条件更新，后台线程与手动触发并发不会重复发布。
- **一稿多号**：`UNIQUE(draft_id, account_id)` + 事务内批量入队；失败时整批回滚。
- **平台一致性**：入队前校验草稿平台与账号平台一致；未接入平台在 `_ready_platform` 拒绝。
- **事务边界**：嵌套事务不再提前提交；迁移仍在 `init_db` 单事务内完成。
- **已发布合并**：平台缓存优先，本地记录占位，模拟记录排除；同一 `(account_id, remote_note_id)` 只出现一次；超限显式标记截断。
- **同步并发**：同账号非阻塞锁；`sync` 与 `publish` 分道；发布中跳过同步。
- **删除链路**：删草稿清图片 / 记录 / 任务；删账号清 `published_notes` / `rate_events` 并解绑草稿、任务；删定时任务清运行记录。

## 7. 安全专项

| 面 | 结论 |
| --- | --- |
| 密钥存储 | 密钥与数据目录分离，Windows ACL 只授当前用户，启动检查；旧密钥自动迁移 |
| 路径穿越 | `/assets/{draft_dir}/{filename}` 校验前缀、拒绝 `/` 与 `\\`、`resolve()` 后校验父目录；目录静态路由不能越出根目录 |
| 上传 | 扩展名白名单 + 文件头校验 + 单张 12MB；文件名不参与落盘路径（UUID） |
| 命令执行 | 无头浏览器用参数列表调用 `subprocess.run`，无 `shell=True`，带超时；`icacls` 同样参数列表调用 |
| 依赖 | 直接依赖锁版本；`curl_cffi==0.16.3` 是发布链路要求 |
| 日志泄漏 | 日志落 `datas/ops/logs/ops.log` 并轮转；平台异常原文只进日志，不写接口 |
| Cookie 加密 | Fernet（AES-CBC + HMAC）；密钥更换后解密失败会提示重新登录 |
| SQL 注入 | 业务 SQL 全部参数化；`ORDER BY` 使用白名单；`PRAGMA table_info` 的表名来自固定集合 |
| XSS | 后端不拼接 HTML；新增 CSP、nosniff、X-Frame-Options |
| 本机边界 | 默认 `127.0.0.1`；无鉴权（P0-1）；接口不返回 Cookie |
| 多平台新面 | `platform` / `content_type` 入库前归一化，未知平台直接拒绝；同步接口仍可被本机程序反复触发（P0-1） |

## 10. 剩余风险与建议

1. **P0-1 本机鉴权**：仍是最大风险；一旦需要跨机器访问，必须先补鉴权再开放监听地址。
2. **同步与发布并发打平台**：分道锁解决了「发布被堵」，但极端情况下同一账号的只读请求与发布仍可能同时进行；已用「发布中跳过同步」降低概率，后续可加平台级软限流。
3. **旧数据空值语义**：升级前已同步的记录仍保留 0，需要重新同步一次才会显示 `null`。
