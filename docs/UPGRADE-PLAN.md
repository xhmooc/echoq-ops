# EchoQ-Ops 升级改造方案（对标 Easel × 出图/视频能力）

> 版本：v1.1 · 2026-11-24
> 状态：首批风格取向已确认（实用信息流）；执行顺序已确认——先完成文档评审，产品代码暂不动
> 关联阅读：对标分析（Easel）、docs/ARCHITECTURE.md、docs/PLATFORMS.md

---

## 0. 背景与结论

对 [ZJU-REAL/Easel](https://github.com/ZJU-REAL/Easel) 及三个出图/视频向项目（[huashu-design](https://github.com/alchaincyf/huashu-design)、[anidoodle](https://github.com/alexgreensh/anidoodle)、[baoyu-skills](https://github.com/JimLiu/baoyu-skills)）完成了一轮学习。结论：

1. **Easel 与我们是同赛道、不同路线**。它是 Agent 驱动（OpenClaw 编排 113 个技能），我们是确定性工作流。它的**账号画像、发现/归因闭环、内容日历、人工发布模式**值得吸收；它的 Agent 化架构不适合直接照搬。
2. **出图能力可以整体升级一代**：从「固定 HTML 模板 + 截图」升级为「风格库 × 版式矩阵 + 多候选 + 设计体检 + 外观账本」，全部仍走本地 HTML/CSS/JS + Chromium 截图，**不引入付费出图依赖**。
3. **手绘风出图有成熟代码化方案**（anidoodle）：风格即绘制规则、种子可复现、零版权风险，可作为我们「免费模板」体系的新来源。
4. **视频按既定定位后置但路线已清晰**：图文为主、视频为辅。近期只做「封面 6 秒循环动效（GIF+MP4）与实拍混合图」，技术上用 HTML 动画/代码绘制 + Chromium 逐帧渲染 + FFmpeg 合成，全程本地、零 API 成本。

总体策略：**不推翻现有架构**（Electron + aiohttp + SQLite），以「能力模块」方式分期引入，保持平台适配器骨架稳定——后续接新平台、新风格、新动效都只做加法。

## 1. 对标项目学习摘要

### 1.1 Easel（ZJU-REAL/Easel）— 运营侧标杆

| 机制 | 内容 | 对我们的启示 |
| --- | --- | --- |
| 五段工作流 | 发现 → 策划 → 创作 → 发布 → 归因 | 我们的链路是「选题→写稿→配图→预览→发布→回收」，缺「发现」与「归因→画像」两环 |
| 账号画像 | 每账号六维：定位/风格/受众/平台/偏好红线/长期记忆，跨会话沉淀 | 最大可借鉴点；让文案、配图、选题越来越贴合账号 |
| 内容日历 | 选题、草稿、待发、已发、平台活动统一到日历视图 | 可作为发布队列的可视化升级 |
| 归因复盘 | 发布后数据回流，把有效结构沉淀进画像 | 与我们已有的「回收（6 小时同步）」衔接，补上「数据→策略」一步 |
| 人工发布模式 | AI 排版 → 人工审核 → 导出 → 官方页面手动提交 | 小红书等风控严格平台的低风险发布选项，与现有「直接发布」并存 |
| 风险提示 | 明确提示小红书自动化检测风险 | 我们已有风控冷却/限流前置，保持并加强提示 |

**不照搬的部分**：OpenClaw/Agent 运行时、113 技能的 SKILL.md 体系、Web 工作台形态。我们保持确定性引擎 + Electron 桌面形态。

### 1.2 huashu-design（alchaincyf/huashu-design）— 出图/动效方法论

MIT 许可。核心是「一句话需求 → 多方向候选 → 设计体检 → 交付」：

- **风格库带样张**：84~92 种风格，每种有真实样张，先看样张再选型；
- **多候选机制**：先出 6 张缩略图，挑 3 版做成真稿（三套选型逻辑：最佳设计师 / 同媒介获奖作品 / 随机轮盘）；
- **设计体检**：碰撞、越界、事实核查；6 维度专家评审（概念一票否决 + 5 执行维度）；
- **小红书图文范式**：3:4 一组图（≤18 张）、8 种版式范式、长卷连续滑动、一条命令切图并体检；
- **时间轴动画**：HTML 动画 → MP4（25/60fps）+ GIF（palette 优化）+ BGM，8-12 分钟交付；
- **外观账本**：记住最近交付用过的风格，主动避免重复（如「最近 6 张里 5 张无衬线标题 → 这版换宋体」）。

对我们的价值：**免费模板体系的产品化方法论**——风格库、样张预览、多候选、体检、账本全部可以落地，且与现有「HTML/CSS 模板 + Playwright 截图 + 碰撞自检」技术栈完全同构。

### 1.3 anidoodle（alexgreensh/anidoodle）— 代码化手绘引擎

Apache 2.0。核心思想：**手绘即代码**，每一笔是一个函数，同一源码在任何机器、任何尺寸渲染出完全相同的图。

- **32 种手绘风格**：铅笔淡彩、水墨、木刻/浮世绘、像素、risograph、剪纸拼贴、刺绣、油画等，每种是一套可复现的绘制规则；
- **绘制过程即动画**：同一份源码既出成图，也出「按画师作画顺序逐笔生长」的 timelapse 视频——水彩先铺铅笔稿再由浅入深、木刻先印主版再套色；
- **代码作曲**：21 种音乐风格的配乐以数据形式写出，另有音效包（可选，373MB）；
- **多画幅重构图**：16:9 / 1:1 / 4:5 / 9:16 同一内容按画幅重新构图，文字在手机上保持可读；
- **交互插画**：`<ani-doodle>` Web Component，吉祥物跟随光标、随滚动自绘，尊重 reduced-motion。

对我们的价值：**免费手绘风配图 + 封面循环动效的引擎级方案**。引入 3~5 个风格（如铅笔淡彩、marker comic、flat vector、水墨、剪纸）作为可复现模板；「绘制过程动画」直接对应我们规划中的「封面 6 秒循环动效」。

### 1.4 baoyu-skills（JimLiu/baoyu-skills）— 内容发布技能集

MIT-0（ClawHub 发布件）。20+ 技能，与我们直接相关的：

- **baoyu-xhs-images**：小红书图卡系列生成器——内容自动拆成 1~10 张卡通图卡，**Style × Layout 双维度系统** + 调色板覆盖；
- **baoyu-format-markdown**：把草稿整理成结构化 Markdown（标题/摘要/加粗/列表）；
- **baoyu-markdown-to-html / baoyu-post-to-wechat**：Markdown → 微信公众号可用 HTML 的转换与发布链路；
- **baoyu-cover-image / baoyu-article-illustrator**：文章封面图与配图生成。

对我们的价值：**Style × Layout 矩阵**可直接套进我们的小红书模板选择器；**公众号 Markdown→HTML 排版链路**可对照我们现有排版器查漏补缺（样式内联、图片转存、代码高亮、引用块等细节）。

### 1.5 汇总：四者拼图

```
Easel          → 运营智能层（画像 / 发现 / 日历 / 归因 / 人工发布）
huashu-design  → 出图与动效的产品方法论（风格库 / 多候选 / 体检 / 账本 / 小红书范式）
anidoodle      → 手绘出图与绘制动画的引擎（可复现 / 零版权 / 多画幅）
baoyu-skills   → 图卡矩阵与公众号排版的具体实现参考
```

## 2. 升级改造总体方案

### 2.1 原则（沿用既有工程约束）

1. 保留现有优质实现，补分层，不整体重写；
2. Electron 桌面端是唯一交付形态；
3. 平台适配器骨架不动，新能力以「服务模块 + 前端面板」挂载；
4. 出图/动效**全部本地生成**（HTML/CSS/JS + Chromium 渲染 + FFmpeg 合成），不新增付费 API 依赖；付费出图入口保留但默认不引导；
5. 所有产物落盘前必须通过设计体检（碰撞/越界），不合规则不出图；
6. 图文为主、视频为辅；视频近期只做动效与图文转视频，不做 AI 生视频。

### 2.2 能力地图（现状 → 目标）

| 能力 | 现状 | 目标（本期改造后） |
| --- | --- | --- |
| 小红书配图 | 固定免费模板 + 付费出图 tab；碰撞自检 | 风格库（带样张）× 版式矩阵 × 多候选；体检升级（重叠/越界/留白比例/字号量级）；外观账本防重复 |
| 手绘配图 | 无 | 3~5 种代码化手绘风格，种子可复现，归入免费 tab |
| 公众号排版 | 已有排版器 | 对照 baoyu 链路补齐：样式内联、图片转存、代码块、引用/分割线等 |
| 封面动效 | 规划中 | HTML 动画/手绘过程 → GIF + MP4（6 秒循环），3:4 / 1:1 / 16:9 多画幅 |
| 图文转视频 | 无 | 图组 + 字幕 + 配乐 → 竖版 MP4（Ken Burns / 绘制过程），FFmpeg 本地合成 |
| 账号画像 | 无 | 六维画像 + 发布数据沉淀（归因） |
| 选题发现 | 选题池（手动/关键词） | 热点雷达：热榜聚合 + 关键词挖题（沿用现有渠道），进入选题池打分 |
| 内容日历 | 发布队列列表 | 日历视图：选题/草稿/待发/已发/定时 |
| 发布模式 | 自动发布 + 发布前检查 | 增加人工发布模式（排版→审核→导出→手动提交），可按平台开关 |
| 归因复盘 | 回收（6 小时同步缓存） | 回收数据写入画像：哪类选题/风格/发布时段表现好，反哺创作建议 |

> M0 不改产品代码，只在 `design-lab/`（实验区）内进行，避免与主线冲突。

### M1 出图体系 2.0（核心，图文主业）

**目标**：免费出图从「固定模板」升级为「风格库 × 版式矩阵 + 多候选 + 体检 + 账本」。

| # | 任务 | 说明 | 涉及 |
| --- | --- | --- | --- |
| 1.1 | 模板数据结构升级 | 模板 = 风格（视觉语言）× 版式（信息排布）两个正交维度；每模板带样张缩略图、适用场景、默认调色板 | ops 出图服务、web/static |
| 1.2 | 首批风格库（**已定向：实用信息流**） | 6 风格 × 4 版式，全部本地 HTML/CSS。风格：① 知识卡片 ② 步骤清单 ③ 数据信息图 ④ 对比测评 ⑤ 大字公告 ⑥ 图注解读；版式：单图大标题 / 上下图文 / 左右分栏 / 长图分页（对齐 huashu 小红书范式 + baoyu Style×Layout） | ops/web/static |
| 1.3 | 样张预览与选择 UI | 免费模板 tab 改为「风格卡片（带样张）→ 版式 → 调色板」选择；保持标签式交互、无原生弹窗 | web/static |
| 1.4 | 多候选生成 | 一次需求可生成 2~3 个候选版式并排预览，用户点选后进入正文编辑 | 出图服务 + 创作页 |
| 1.5 | 设计体检升级 | 在现有碰撞/越界基础上增加：留白比例（内容 ≥70%、底部留白 ≤ 顶部 1.2 倍）、字号量级、长文自动分页检查；不通过不出图并给出原因 | 出图服务（自检模块） |
| 1.6 | 外观账本 | 每账号记录最近 N 次出图的风格/版式/调色板；推荐时主动避开连续重复 | SQLite 表 + 出图服务 |
| 1.7 | 公众号排版补齐 | 对照 baoyu-post-to-wechat：样式全内联、图片转存、代码块/引用/分割线处理、移动端字号行距 | 排版器 |

**验收**：同一篇文案能一键得到 3 个不同风格候选；任一候选逐张通过体检；连续 5 次出图不出现完全相同风格组合；公众号预览与线上编辑器样式一致。

### M2 手绘引擎接入

**目标**：引入代码化手绘风格，作为免费出图的差异化亮点；零版权风险、可复现。

| # | 任务 | 说明 |
| --- | --- | --- |
| 2.1 | 绘制引擎抽象 | 定义「风格 = 一组绘制原语（笔触/填充/纹理）+ 构图规则 + 种子」的接口，渲染仍走 HTML Canvas/SVG + Chromium 截图 |
| 2.2 | 首批 3~5 风格 | 建议：flat vector（科技感）、pencil & watercolour（生活感）、marker comic（活泼）、sumi-e（国风）、cut-paper（节日）；参考 anidoodle 规则自研实现 |
| 2.3 | 可复现性 | 同（内容，风格，种子）输出逐像素一致；种子随草稿保存，支持「换一张」 |
| 2.4 | 与模板体系整合 | 手绘风格作为风格库中的分类进入 M1 的选择 UI 与体检流程 |

**验收**：手绘风格出图通过全部体检项；同种子重渲染一致；风格样张进入预览选择 UI。

### M3 动效与图文转视频（视频为辅，按既定边界）

**目标**：交付「封面 6 秒循环动效（GIF+MP4）」与「图组转竖版视频」，全程本地生成。

| # | 任务 | 说明 |
| --- | --- | --- |
| 3.1 | 动效模板体系 | 3~5 个动效范式：文字逐字浮现、手绘生长（复用 M2 绘制过程）、图片 Ken Burns、贴纸弹跳、进度条收尾；参数化（时长/画幅/配色） |
| 3.2 | 渲染管线产品化 | M0 PoC 固化为服务：动效 HTML → 帧序列 → FFmpeg（GIF palette 优化 + MP4 H.264）；复用现有隐藏窗口渲染方案，避免窗口反复创建 |
| 3.3 | 多画幅输出 | 3:4（小红书/抖音图文）、1:1、16:9；同一动效按画幅重排构图，文字不裁切（体检扩展到动效首尾帧） |
| 3.4 | 实拍混合图 | 用户实拍图 + 模板贴纸/文字/边框合成（Canvas 合成后统一出图） |
| 3.5 | 图组转视频 | 已生成图组 + 字幕 + 内置免费配乐（代码合成短_loop，参考 anidoodle 作曲思路）→ 竖版 MP4；不做口播、不做 AI 生视频 |
| 3.6 | 配乐（可选） | 内置少量免版权短 loop；不做 AI 作曲依赖 |

**验收**：6 秒循环动效在 3:4/1:1/16:9 三画幅均无文字裁切、循环点无跳变；GIF < 5MB、MP4 1080p；图组转视频 ≤ 30s 内完成（10 张图内）。

### M4 运营智能 v1（借鉴 Easel）

**目标**：把「回收数据」变成「创作策略」，补上 Easel 最有价值的画像-归因闭环。

| # | 任务 | 说明 |
| --- | --- | --- |
| 4.1 | 账号画像模型 | 新增画像表：定位、风格关键词、受众、平台偏好、偏好红线、统计摘要；创作页按账号带出画像上下文（写入文案生成的 prompt 约束） |
| 4.2 | 内容日历视图 | 运营管理页新增日历面板：选题/草稿/待发/已发/定时按日呈现；数据来自现有队列与内容库，不另起炉灶 |
| 4.3 | 归因写入 | 回收同步（6 小时任务）后，按内容聚合曝光/互动，写入画像统计：高表现选题特征、风格、发布时段 |
| 4.4 | 创作建议 | 创作页展示轻量建议（如「近 30 天『教程类+手绘风』互动率最高」），只读提示，不强制 |
| 4.5 | 人工发布模式 | 按平台可配置：排版 → 预览确认 → 导出（图组/HTML/文案包）→ 用户在官方页面手动提交；状态标记「已导出/已人工发布」与自动发布队列区分 |

**验收**：画像字段可编辑并影响文案生成；日历能正确呈现全状态内容；归因数据随回收任务自动更新；人工发布流程可完整走通小红书一例。

### M5 热点发现（可选，画像就绪后）

## 4. 学习计划（落地路径）

| 阶段 | 动作 | 产出 |

## 5. 风险与边界

| 风险 | 对策 |
| --- | --- |
| 小红书自动化风控 | 发布侧维持限流前置、冷却、退避；提供人工发布模式作为低风险通道；产品内保留风险提示 |
| 版权 | 全部风格/模板/配乐为自研代码实现或免版权素材；不引入需授权的字体/图库；anidoodle/huashu 仅学习思想，代码不直接拷贝（各自 Apache/MIT 许可若需引用将单独评估并记录） |
| 性能 | 动效渲染逐帧截图耗时可控（6s×25fps=150 帧）；渲染走复用的隐藏窗口；视频合成用 FFmpeg 子进程，不阻塞 UI |
| 范围蔓延 | 视频严格限定在「动效 + 图文转视频」，AI 生视频、口播、剪辑等一律不入本期范围 |
| 与并行开发冲突 | M0 全部在 `design-lab/`；M1 起涉及 ops/web/static 的改动按模块拆分提交，遵循「界面改动最小化」约束 |
| 体检误杀 | 体检规则先「告警模式」观察一周，再切「强制模式」 |

## 6. 验收与度量

- **出图**：候选生成成功率、体检通过率、用户点选率（候选 vs 最终稿）、重复风格率（账本）；
- **动效/视频**：单条生成耗时、文件体积、循环无跳帧抽检；
- **运营智能**：画像填写率、归因数据更新及时性、建议点击率；
- **发布**：人工模式走通率、自动发布成功率不回退；
- 每期结束更新 `docs/CHANGELOG.md`，版本号按规则递增（功能更新 0.1.x +1）。

## 8. 更新路径（版本与发布）

按既有版本规则执行：功能更新末位 +1（0.1.0→0.1.1）；大版本中位 +1、末位归零（0.1.x→0.2.0）；版本号仅维护在 `ops/__init__.py` 与 `electron/package.json` 两处，保持一致。

| 版本 | 对应里程碑 | 交付内容 | 发布物 |
| --- | --- | --- | --- |
| 0.1.x | 当前基线 | 已上线能力 + 评审问题修复 | 已发布 |
| （不发版） | M0 | 学习笔记（docs/notes/）、两个 PoC（design-lab/ 内） | 无 |
| **0.2.0** | M1 | 出图体系 2.0：实用信息流 6 风格 × 4 版式、样张预览、多候选、体检升级、外观账本、公众号排版补齐 | 安装包 + 便携包 |
| 0.2.1 ~ 0.2.2 | M2 | 手绘引擎接入，3~5 风格并入免费 tab | 安装包 + 便携包 |
| **0.3.0** | M3 | 封面 6 秒循环动效（GIF+MP4）、多画幅、实拍混合图、图组转竖版视频 | 安装包 + 便携包 |
| **0.4.0** | M4 | 账号画像、内容日历、归因写入、人工发布模式（小红书首发） | 安装包 + 便携包 |
| 0.4.1+ | M5（视情况） | 热点雷达、选题评分 | 安装包 + 便携包 |

每个版本发布 checklist：

1. 同步修改 `ops/__init__.py` 与 `electron/package.json` 的版本号；
2. 更新 `docs/CHANGELOG.md`：新功能、行为变化、已知问题；
3. 执行 `build/build-desktop.ps1`，产物统一入 `release/`；
4. 涉及界面改动的版本，更新 `docs/ui/` 截图与 README 界面图；
5. 冒烟：创作 → 出图 → 预览 → 发布（小红书/公众号/抖音各一）；动效/视频版本加样片抽检；
6. 数据目录迁移（如涉及新表）需兼容 `%LOCALAPPDATA%\EchoQ-Ops\data` 既有数据。
